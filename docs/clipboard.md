# Clipboard history

Search for **clipboard** (or **剪贴板**) and select the command. The picker then searches only your clipboard history. Ordinary window and alias searches do not include copied text.

History starts recording new text and image copies while Winlane is running. It does not import whatever was on the clipboard before startup or collect copies made while recording was paused. Text, URLs, screenshots and copied PNG/TIFF images are supported. File copies and rich-text formatting are not retained. An image takes priority when the clipboard also includes an image caption or URL.

## Find and reuse a copy

- Type words from the copied text or its source app. Use `image`, `screenshot`, `图片` or `截图` to find images. Results stay in most-recently-copied order. Copying identical text again moves its existing entry to the top.
- Use the arrow keys or click a row to select it. **Enter** or a row click pastes its text or original image into the app you were using before opening Winlane.
- **Command + C** copies the selected entry and closes the picker without pasting.
- **Command + Backspace** deletes the selected entry from history.
- **Esc**, the back button, or Backspace in an empty query returns to window search.

The **Actions…** menu also provides Copy, Delete, Pause/Resume Recording, and Clear History. Image rows show a thumbnail, pixel dimensions and file size. Hover over a row for a longer text preview and its copy time. Clear History asks for confirmation and leaves the current system clipboard unchanged.

Pasting waits for the previous app to gain focus and for modifier keys to be released. If the app exits or focus moves elsewhere, Winlane reports an error instead. It does not press Enter in the destination app. Copies generated by Winlane's history and snippet actions are not recorded again.

## Retention and privacy

**Settings → Clipboard** saves changes automatically:

| Setting | Default | Range / behavior |
| --- | --- | --- |
| Record clipboard history | On | Pause capture while keeping existing history available. |
| Save on this Mac | On | Keep history across restarts. Turning this off deletes the disk file and keeps current entries for the session. Text stays in memory; images use private temporary files removed on normal quit. |
| Maximum entries | 200 | 1–1000; oldest entries are removed first. |
| Retention in days | 7 | 1–365; expired entries are removed even while capture is paused. |

The history index and text are **unencrypted**, local to this Mac, at:

```text
~/Library/Application Support/Winlane/Clipboard/history.json
```

Original images and 96-pixel thumbnails are stored beside the index in `Clipboard/images/`. Only metadata and small thumbnails stay in memory; originals are read when copying or pasting. Deleting, clearing or expiring a record also removes its retained image files.

The history directory is restricted to the current user (`0700`), and the file uses `0600` permissions. File writes happen in the background and replace the previous file atomically. A corrupted file is preserved instead of silently overwritten; use Clear History to discard it and start again. Disabling disk storage also removes that file.

Winlane skips copies carrying standard concealed, transient, or autogenerated pasteboard markers, as well as copies detected from common password managers. This cannot identify every secret: unmarked passwords or tokens copied from ordinary apps may still be recorded. Pause recording before copying anything you do not want saved. Clipboard contents are never uploaded by Winlane.

To bound resource use, one item can contain up to 64 KiB of UTF-8 text, and retained text totals at most 4 MiB, even if the entry-count limit has not been reached. Images are limited to 32 MiB and 100 megapixels each, and 128 MiB in total. Text and images share the entry count and retention period; reaching a limit removes older entries of that type. Winlane checks the clipboard change counter twice per second and reads contents only after a change. Image decoding, thumbnail generation and storage run in the background, one image at a time. Several copies made between checks can therefore collapse into the latest one. Source labels reflect the foreground app when a change is observed.
